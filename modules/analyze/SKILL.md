# 审题与路线

输入：原始题面、已有研究状态、用户的时间/资源约束。输出：逐项可检查的题目要求、关键定义、候选路线及最小可检验模型。

## 执行

1. 读完整题面，保留原文；检查截断、遗漏公式/图示。把“解释、比较、求阈值、给方案、写操作说明”转换为具体交付，编号 R1、R2…；把补充研究目标与原题要求分开。
2. 建立已知量、待求量和缺口表。含糊词如“有效、显著损害、自然音色、可行、最大”需要操作定义。优先给有依据的范围或多个定义下的条件结果，不擅自变成单一阈值。
3. 明确参考系、时间/空间范围、成功事件、边界与可控变量。区分共同海拔与相对高度、峰值与稳态、机械能与可用能量、真实实验与模型计算。
4. 识别瓶颈：机制精度、参数缺失、方案选择、实验可行性，或成果表达。选择 [机制路线](../../references/branches/mechanism.md) / [设计路线](../../references/branches/design.md)，允许混合。
5. 在值得比较时给出 2–3 条路线：能回答什么、需要什么数据、主要假设、成本和可验证性。选一条足以回答核心问题的基线；只有新机制会改变决策或误差时才升级。
6. 排工作顺序：先可解性与数量级，再基线答案；在批量计算前完成会决定主模型可信度的代表检查。区分原题必答、可信度必需和解释性补充，按资源推进，避免补充探索挤掉主答案与写作。论文论证提纲可早建立，摘要和确定数值最后写。昂贵任务的选点、上限和重试依据见 [执行判断 §1](../../references/research-execution.md#1-先做能改变路线的检查)。

缺少时间限制时不虚构赛程。备赛时解释选择依据；比赛执行时围绕当前最重要的证据缺口推进。已有代码/数据时先检查其能覆盖哪些要求，避免重建所有内容。

## 离开本阶段的标准

- 每条要求都有预期回答形式和验证思路。
- 影响路线的关键模糊处已解决，或明确作为情景分支。
- 给出能实际开始的下一步，如查一个参数、推一个守恒式或运行一个基线，不止“深入研究”。
